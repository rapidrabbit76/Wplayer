# Contributing to Wplayer

Thanks for helping. Bug reports, translations and pull requests are all welcome.

## Reporting bugs

Open an issue with the bug report template. Include the device and Android version, the protocol (SMB, NFS,
FTP, WebDAV or local storage) and, for playback problems, the codec and container (the playback stats overlay in
Settings → General → Developer shows them). Logs help: `adb logcat --pid=$(adb shell pidof dev.wplayer)` while reproducing.

Never attach credentials, server addresses you would rather keep private, or personal media.

## Development setup

Follow [Build](README.md#build) in the README. In short:

```sh
cd android
source ./env.sh            # adjust for your machine, or set the variables yourself
native/build.sh            # once; libmpv, FFmpeg and friends for both ABIs
./gradlew :app:assembleDebug
```

Before opening a pull request, run what CI runs:

```sh
(cd rust && cargo fmt --check -p wplayer-core && cargo clippy -p wplayer-core --all-targets -- -D warnings && cargo test -p wplayer-core)
(cd android && ./gradlew :app:testDebugUnitTest :core:native:testDebugUnitTest :app:lintRelease)
```

Lint warnings fail the build. Fix them; suppress one only in [`android/app/lint.xml`](android/app/lint.xml) with a comment saying why.

## Code

- **Layout**: a monorepo. `rust/` holds the core shared by every platform; `android/` is the Gradle project
  (`app`, `core/native`, `baselineprofile`) with its libmpv build in `android/native/`. Paths below under `app/` and
  `native/` are relative to `android/`.
- **Architecture**: unidirectional data flow. ViewModels expose `StateFlow<UiState>`; composables render state and
  send events up. Data goes through repositories (Room, DataStore, the Rust core); dependencies come from Hilt.
- **Rust core** (`rust/wplayer-core`): protocols, the libmpv bridge, thumbnails, downloads and speech
  recognition. Its Kotlin bindings are generated by UniFFI during the Gradle build; do not edit them.
- **Native libraries** are pinned in `native/versions.env`. Patched third-party crates live in `rust/patches/`
  with each change marked `[wplayer patch]` and listed in `rust/patches/README.md`.
- **Style**: follow the surrounding code. Comments explain *why*, not what the next line does. KDoc on public types
  and non-obvious functions. `.editorconfig` sets the basics.
- **Tests**: unit tests for logic (`app/src/test`, `rust/…/tests` and `#[cfg(test)]` modules). Protocol tests that
  need real servers are `#[ignore]`d; run them with `scripts/test-servers.sh` as described in the README.
- **Dependencies**: prefer AndroidX and the libraries already used. A new dependency needs a reason in the pull
  request and must be GPL-3.0-compatible; it then shows up under Settings → About automatically (native
  libraries need an entry in `app/aboutlibraries/libraries/` and in `THIRD_PARTY_NOTICES.md`).

## Translations

Strings live in `app/src/main/res/values/strings.xml` (English, the default) and `values-<language>/strings.xml`.
To add a language:

1. Copy `values/strings.xml` to `values-<code>/strings.xml` and translate it (keep `%1$s`-style placeholders;
   use `<plurals>` where counts appear). Leave out `translatable="false"` strings.
2. Add the language to `AppLanguage` in `app/src/main/java/dev/wplayer/app/ui/settings/AppLanguage.kt`.
3. Add its code to `localeFilters` in `app/build.gradle.kts`.
4. Optionally translate the README into `docs/translations/README.<code>.md` and link it at the top of `README.md`.

## Commits and pull requests

- One logical change per commit. The subject says what changes in the imperative mood, under about 70 characters;
  the body explains why when it is not obvious.
- Keep pull requests focused; describe how you tested (device or emulator, protocol, sample files).
- By contributing you agree that your contribution is licensed under the
  [GPL-3.0-or-later](LICENSE), like the rest of the project.
